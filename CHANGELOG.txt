 NEW FILES
===========================================================================
 app/lib/sanitizeUrl.ts
   URL scheme allow-list used everywhere user links/images are rendered.
     - safeUrl()      : allows http/https/mailto/tel + relative/anchor links;
                        neutralizes javascript:, data:, vbscript:, etc.
     - safeBgUrl()    : http(s) only, and rejects characters that could break
                        out of a CSS url(...) wrapper.
     - safeImageUrl() : (added as a follow-up) http(s)-only for <img src>.

 app/lib/reserved.ts
   RESERVED_SLUGS deny-list + isReservedSlug() + cleanSlug()
   (lowercases, strips invalid chars, collapses/trims hyphens, caps len 63).

 app/lib/rateLimit.ts
   Per-account save quota helpers: addQuotaWrite(batch, uid) + newBatch().
   Current setting: 10 saves per rolling 5 hours (MAX_ACCOUNT_WRITES=10,
   ACCOUNT_WINDOW_MS=5h).

 firestore.rules
   Ownership- AND quota-enforced rules. Replaces the old live rules.

 firestore.indexes.json
   Empty index config required by the deploy.

 firebase.json
   Deploy config. Firestore-only (the storage block was removed because the
   app does not use Firebase Storage).

 storage.rules
   Lock-down for Firebase Storage (read public, write denied). Now ORPHANED —
   not referenced by firebase.json — safe to delete since Storage is unused.

 SECURITY_AUDIT.txt
   Full findings report + remediation status.

===========================================================================
 RATE LIMITING  (new feature)
===========================================================================
 Per-IP  : 50 requests / 60s sliding window in middleware.ts -> HTTP 429.
           (In-memory per edge instance; back with Redis/Upstash for a strict
            global limit.)

 Per-account : counter at rateLimits/{uid} written in the SAME batch as the
           profile/site write. dashboard + builder save paths were rewritten
           to batched writes (unused setDoc imports removed). firestore.rules
           enforce it server-side via getAfter: each content write must carry
           a fresh +1 counter bump, the counter advances at most once per
           write, and resets only after the real window elapses (anchored to
           request.time, with a 5-min client-clock tolerance).
           Current limit: 10 saves per account per 5 hours (see MISMATCH note
           at top).
